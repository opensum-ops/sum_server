Download and inspect it, then install and enroll as separate steps.

curl -fsSL {{ server_url }}/install.sh -o install.sh
less install.sh
sudo sh install.sh
sudo SUM_AGENT_SERVER_URL={{ server_url }} SUM_AGENT_STATE_DIR={{ state_dir }} \
    {{ bin_path }} enroll --token {{ enrollment_token }}
sudo systemctl enable --now {{ service_name }}

The SUM_AGENT_STATE_DIR on the enroll line is not optional: it has to match what the unit passes, or enrollment is written where run will not find it.

What the script does
  • Refuses to run unless it is root, on x86_64, with systemd present.
  • Downloads the agent from this server and verifies its SHA-256 before installing.
  • Installs {{ bin_path }}, writes /etc/sum-agent/agent.env and the systemd unit.
  • Keeps state in {{ state_dir }}, and runs as root so the agent can replace its own binary when you push an update.
  • Is safe to re-run: it upgrades the binary in place and will not re-enroll a host that already has state.

Enroll manually

If the agent is already installed on the host:

export SUM_AGENT_SERVER_URL={{ server_url }}
sum-agent enroll --token {{ enrollment_token }}

systemd service

cat <<'EOF' | sudo tee {{ unit_path }}
[Unit]
Description=OpenSUM agent
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
Environment=SUM_AGENT_SERVER_URL={{ server_url }}
ExecStart={{ bin_path }} run
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now {{ service_name }}

The ordering on network-online.target also matters at shutdown: it lets the agent send its goodbye report before the network goes away, so the host shows as rebooting/powered off instead of unreachable.
